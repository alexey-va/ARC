# Таблицы с рамками RusCrafting

Готовый конструктор принадлежит модулю `arc-core-paper-menu`:
[`DialogTables`](../../arc-core/arc-core-paper-menu/src/main/kotlin/ru/arc/paper/menu/DialogTables.kt).
Он использует те же рамки и отступы, что `/arc dialogdemo tables-5` и `tables-6`.
Для новой таблицы достаточно выбрать стиль и передать пары «подпись — значение»:

```kotlin
import net.kyori.adventure.text.Component
import ru.arc.paper.menu.DialogTables

val summary = DialogTables.body(
    rows = listOf(
        text("owner-label") to Component.text(ownerName),
        text("members-label") to Component.text("$members / $limit"),
        text("location-label") to Component.text("$x, $y, $z"),
    ),
    spec = DialogTables.Spec(rowSeparators = true),
    headers = text("label-heading") to text("value-heading"),
    frame = DialogTables.Frame.COMMON,
)
// PaperDialogScreen(..., body = listOf(summary), buttons = existingActions)
```

`text(...)` в примерах — существующий locale/config-резолвер своего меню.
Названия полей храните в его ресурсах. Имена игроков и прочие внешние значения
передавайте как `Component.text(...)` или через unparsed/component placeholders;
не разбирайте их как MiniMessage. Компоненты сохраняют свои цвета и события.
Без собственного цвета подписи серые, значения светлые; заголовки золотые.

| Стиль | Эталон | Когда подходит |
|---|---|---|
| `COMMON` | T13 | Простая нейтральная сводка, профиль, координаты или параметры объекта |
| `UNCOMMON` | T14 | Данные о земле, природе или состоянии с зелёным акцентом |
| `RARE` | T15 | Техническая справка, маршруты или другие уместные синие акценты |
| `EPIC` | T16 | Карточка с фиолетовым акцентом под содержание экрана |
| `LEGENDARY` | T17 | Подробная карточка поселения, объекта или прогресса с золотым акцентом |
| `ARTIFACT` | T18 | Данные данжа, сложность, прохождение и другие уместные красные акценты |

Все шесть текстурных рамок T13–T18 — полноценные варианты. Выбирайте их по
содержанию и композиции экрана, сохраняя разнообразие между разными экранами и
единство внутри связанной группы таблиц. Простые T13–T15 подходят обычным
сводкам; `EPIC` не является визуальным вариантом по умолчанию. Название рамки
не назначает предмету редкость и не заменяет словесное состояние. T1–T12 в
демонстрации используют обычный текст и Unicode, а не эти bitmap-рамки.
Правила, предупреждения, длинные объяснения и одиночные сообщения оставляйте
обычным текстом; действия остаются в кнопках native dialog.

## Размеры без ручной подгонки

- `body` по умолчанию использует `width = 320`, включая внутренние 4 px с каждой
  стороны. Короткие каталоги могут использовать `280`, как магазин ArcFarms.
  Не наследуйте ширину кнопок или всего диалога: таблице не нужен пустой запас.
  Низкоуровневый `render` сохраняет `400` для совместимости с демо.
- Соседним таблицам задавайте одинаковую ширину и фиксированную пропорцию
  колонок (`BALANCED`, `VALUE_WIDE` или `LABEL_WIDE`), чтобы разделители совпадали.
- `columns = AUTO` выбирает разделение с минимальной суммарной высотой строк.
  Длинное значение переносится в своей ячейке; соседняя получает столько же строк.
- `BALANCED` фиксирует примерно равные колонки; `VALUE_WIDE` оставляет больше места
  значениям. `LABEL_WIDE` повторяет пропорции T13–T18 из демо.
- `headers = null` убирает шапку и её горизонтальный разделитель.
- Разделители строк включаются явно: `spec = DialogTables.Spec(rowSeparators = true)`.
  По умолчанию они выключены; старые вызовы сохраняют исходную JVM-сигнатуру.
  Разделитель шапки независим от этой опции. При включении конструктор добавляет
  между логическими строками тонкий горизонтальный разделитель из уже имеющихся
  glyphs `left_joint`, `top`, `middle`, `right_joint`. Разделитель добавляется
  один раз на строку данных, а не между строками переноса; после последней строки
  дополнительной линии нет. Между переносами внутри одной ячейки линий нет.
- Для низкоуровневого `DialogBody.plainMessage` используйте
  `DialogTables.render(...).component` и **ту же** ширину body.

Конструктор сам выбирает целое количество 9 px плиток, центрирует рамку,
компенсирует advances краёв/стыков и задаёт одинаковый видимый отступ после левой
границы и после центрального разделителя. Не добавляйте пробелы, сырые PUA-глифы,
отрицательные spacer-символы, ручные координаты или второй расчёт ширины в меню.
Не пропускайте уже собранную таблицу через повторный `DialogTextLayout.layout`:
рамка уже выровнена, а её отрицательные глифы относятся к сборке границ.

Измерение и переносы выполняет `arc-core/ComponentTextLayout` с проверенным
снимком шрифтов `DialogTextLayout`. Глифы рамок принадлежат этому адаптеру
ресурспака ARC; копировать конструктор в другой плагин не нужно. Соседний плагин
подключает `arc-core-paper-menu` и использует типизированный API напрямую — без
поиска классов ARC и рефлексивных мостов.

Требуется загруженный ресурспак RusCrafting с `arc:table_tooltip_*` и spacer-глифами
U+F0F01..U+F0F0A / U+F0F11. Это не автоматическое определение клиентского пака.
Неизмеренный шрифт, unresolved translation, слишком узкая область или чрезмерная
таблица дают `Result.Unframed` с исходными данными «подпись: значение», без потери
информации. Для больших каталогов используйте существующую пагинацию; не помещайте
в одну таблицу больше 64 строк.

## Непрозрачная плашка: одна или несколько колонок

`DialogTables.filledBody` — отдельный явный вариант с тёмным фоном и мятной
рамкой v03. Он не меняет шесть `Frame` и требует соответствующий шрифт
`arc:dialog_ui_preview` в клиентском пакете. Примеры доступны в первых четырёх
страницах `/arc dialog preview`.

```kotlin
val panel = DialogTables.filledBody(
    rows = listOf(
        listOf(text("place-label"), Component.text(placeName)),
        listOf(text("route-label"), text("route-description")),
    ),
    headers = listOf(text("label-heading"), text("value-heading")),
    width = 508,
    columnWeights = listOf(2, 3),
)
```

Для одной колонки передавайте одно значение в каждой строке, `headers = null`,
`columnWeights = listOf(1)` и, например, `width = 300`. Три и более колонки
задаются тем же способом. Все аргументы передавайте явно при вызове между
plugin classloader. Допустимы 1–8 колонок с положительными весами; число ячеек
каждой строки и шапки должно совпадать с числом весов. Ячейки переносятся
независимо, вертикальные разделители остаются на фиксированных позициях.

Высота автоматически следует за содержимым: до 64 логических строк, включая
шапку, и до 192 строк после переноса. Более длинный, неподдерживаемый или слишком
узкий текст выводится целиком без рамки; для больших наборов вызывающее меню
может использовать свою пагинацию. Ширина допустима в пределах 9–1024 px;
рамка занимает `width - 10`, оставляя 8 px native padding и 2 px запаса для
проверки промежуточного advance клиентом. Цвет текста по умолчанию светлый
`#e8dfd2`; явно заданные цвета, шрифты, события и тени сохраняются. Весь фон
рисуется до всего текста, поэтому следующие полосы не перекрывают буквы и тени.

## Рабочие примеры

- `HelpCenterController.showNow`, `openHome`, `openPlayer`: профиль, дом и игрок, T16.
- `HelpCenterHubController.openItem`, `openContext`: предмет в руке T13 и окружение T14.
- `HelpCenterSettingsController.openFlight`: запас заряда, заполнение и режим полёта, T15.
- `LandsUiController.openDetails`, `openTerritory`, `openCreated`: поселение и территория, T17.
- `DungeonSaveMenus.panel`, `open`: параметры данжа и число сохранений, T18.
- `DungeonSaveMenus.detail`: тип, время и координаты сохранения, T17.
- `DialogDesignGallery.table`: все шесть эталонов используют этот же API.

`DialogTablesTest` проверяет одинаковую ширину строк всех рамок, переносы,
пустые ячейки и безопасный вывод неподдерживаемого текста. Эталонная галерея
сохраняет ширину 392 px; обычный пакетный build не запускает тяжёлые GUI-тесты.
